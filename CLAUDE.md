# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Full-stack starter kit: **Rails 8.1 backend + React 19 frontend bridged by Inertia.js** (no separate API layer). Inertia controllers render React pages directly and pass typed props; the frontend never fetches JSON — controller actions return page components with props. Based on the Laravel React Starter Kit, with auth derived from Authentication Zero.

## Commands

```bash
bin/setup            # Install deps (Ruby + JS) and boot the server
bin/dev              # Run dev processes from Procfile.dev (Vite + Rails on :3000)
bin/ci               # Full CI suite locally (see config/ci.rb for the exact steps)

bin/rspec                              # Run all Ruby tests
bin/rspec spec/requests/foo_spec.rb    # Single file
bin/rspec spec/requests/foo_spec.rb:42 # Single example by line

bin/rubocop          # Ruby lint/style (Omakase + overrides in .rubocop.yml)
bin/brakeman         # Ruby security scan
bin/bundler-audit    # Gem CVE audit

npm run lint         # ESLint over app/frontend + root config files (--max-warnings 0)
npm run lint:fix
npm run format       # Prettier --check
npm run format:fix
npm run check        # TypeScript typecheck (tsc, no emit) for both tsconfig projects
```

`bin/ci` runs setup → rubocop → JS lint/format/typecheck → security scans → rspec → seed replant. Match it before assuming a change is green.

## Architecture

### Inertia request flow
- Controllers inherit from `InertiaController` (`app/controllers/inertia_controller.rb`), which sets `default_render: true` and shares `auth: { user, session }` to every page via `inertia_share`. Auth-exempt controllers inherit from `ApplicationController` directly.
- `ApplicationController` runs `authenticate` as a `before_action`; the current session/user live in the `Current` model (`app/models/current.rb`), resolved from the signed `:session_token` cookie.
- A controller action like `Settings::ProfilesController#show` with no body renders `app/frontend/pages/settings/profiles/show.tsx`. Page lookup is convention-based (controller path → `pages/` path).
- Validation errors are passed back with `redirect_to ..., inertia: { errors: @model.errors }` and read via the Inertia `<Form>`'s `errors` render prop — not flash.

### Typed routes (Typelizer)
- `app/frontend/routes/*` is **auto-generated by the `typelizer` gem — do not edit by hand** (files carry a "DO NOT MODIFY" digest header). Regenerated as the dev server runs; config in `config/initializers/typelizer.rb` (`/rails` and `/up` excluded).
- Import route helpers from `@/routes`, e.g. `settingsProfiles.update()` returns `{ url, method }` for `<Form action={...}>`, and `settingsProfiles.show().url` for hrefs. After changing `config/routes.rb`, the generated route modules update — re-run the dev server / typecheck rather than editing the TS.

### Frontend layout (`app/frontend/`)
- `pages/` — Inertia page components (entry per controller action). `layouts/` — composable layouts (`app-layout`, `auth-layout`, `settings/layout`); `persistent-layout.tsx` wraps all pages (set as the default layout in `entrypoints/inertia.tsx`).
- `components/ui/` — shadcn/ui (new-york style, Radix-based). Add components via the shadcn CLI; config in `components.json`.
- `hooks/`, `lib/utils.ts` (the `cn()` helper), `types/`. Path aliases `@/*` and `~/*` both map to `app/frontend/*`.
- `entrypoints/inertia.tsx` is the Vite/Inertia bootstrap (title, persistent layout, theme init). `application.css` holds Tailwind v4 setup.

### Build & tooling
- **Vite** (`vite.config.ts`) via `vite_rails` gem + `vite-plugin-ruby`. Plugins: React (with **React Compiler** through the babel plugin), Tailwind v4, Inertia. TypeScript is strict with `noUnusedLocals`/`noUnusedParameters`.
- DB is **SQLite** for all environments; cache/queue/cable use the Solid* adapters (`solid_cache`, `solid_queue`, `solid_cable`). Active Job/Cron run via `bin/jobs`.

### SSR
Ships SSR-ready but **off**. Toggle `config.ssr_enabled` in `config/initializers/inertia_rails.rb`; in dev that alone works (Vite serves SSR with HMR). Production images need `SSR_ENABLED=true` as a Docker build arg. Puma boots the in-process Node renderer via `plugin :inertia_ssr` (`config/puma.rb`); falls back to client rendering on error. See README for full steps.

### Deployment
Docker image (`Dockerfile`) deployed via **Kamal** (`config/deploy.yml`, `.kamal/`), fronted by **Thruster**.

## Conventions

- Ruby style is RuboCop Omakase with overrides (`.rubocop.yml`): **double-quoted strings**, no space inside `[ ]`/`{ }` literals, 2-space indent, frozen-string-literal comments required.
- Tests are **RSpec** (request specs under `spec/requests/`) with **FactoryBot** factories (`spec/factories/`). Capybara + Selenium available for system specs.
- Prettier (with the Tailwind class-sorting plugin) formats the frontend; ESLint enforces import resolution and React hooks rules.
